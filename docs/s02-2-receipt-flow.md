# 실습 ②: 토픽으로 흐름을 호출하는 입구 만들기 (Frontend)
{: .no_toc }

| 시간 | 소요 | 수강생 역할 |
|:-----|:-----|:-----------|
| 09:50 | 8분 | 🟡 따라보기 |

이 페이지에서는 사용자가 **"엑셀분석"** 이라고 부르면 흐름을 호출하는 토픽을 만듭니다. 흐름은 [실습①](s02-1-receipt-prompt) 에서 이미 완성한 상태여야 합니다.

## Step 13. 에이전트 + 토픽 만들기

1. [copilotstudio.microsoft.com](https://copilotstudio.microsoft.com) 접속
2. 새 에이전트: `엑셀 분석 에이전트`
3. **토픽 → 새 토픽 (빈 토픽)**
4. 토픽 이름: `엑셀 분석`
5. 트리거 구문 추가:
   - `엑셀분석`
   - `엑셀 파일 분석해줘`
   - `시트 분석해줘`

---

## Step 14. 질문 노드 두 개 추가

### 질문 노드 ① — 요청문

- 질문 메시지: "어떤 분석을 원하시나요? (예: 사과의 연도별 평균은?)"
- 식별: **사용자의 전체 응답** (텍스트)
- 변수 이름: `Topic.요청문`

### 질문 노드 ② — 파일

- 질문 메시지: "분석할 Excel 파일을 첨부해주세요."
- 식별: **파일** (Identify → File)
- 변수 이름: `Topic.첨부파일`
- **속성 → 고급 → 파일 메타데이터 활성화** ← 매우 중요. 이걸 켜야 파일의 콘텐츠/이름/MIME 타입에 접근 가능

> **포인트**: 파일 메타를 활성화하지 않으면 흐름에 파일을 넘길 때 콘텐츠가 비어 옵니다.

---

## Step 15. 흐름 호출 노드 추가 (record 타입 변환)

1. 새 노드 추가 → **작업 (Action) → 흐름 → `엑셀분석_흐름` 선택**
2. 입력 파라미터 매핑
   - `요청문` → `Topic.요청문`
   - `파일` → 수식(fx) 사용:
     ```
     {
       name: Topic.첨부파일.Name,
       contentBytes: Topic.첨부파일.Content
     }
     ```

> **포인트**: Copilot Studio의 파일 변수와 Power Automate 트리거의 파일 입력은 **스키마가 달라서**, Copilot Studio 쪽에서 record(레코드)로 직접 매핑해줘야 합니다. `Name`, `Content` 두 속성이 핵심입니다.
> (테넌트 버전에 따라 속성 이름이 `Name/Content` 또는 `name/contentBytes` 등으로 다를 수 있으니 흐름 트리거의 입력 스키마와 일치하도록 확인하세요.)

---

## Step 16. 결과 메시지 노드

1. 흐름 호출 노드 다음 → **메시지 노드 추가**
2. 메시지 본문에 흐름 출력 변수 `결과텍스트` 삽입
3. 토픽 저장

---

## Step 17. 전체 테스트

1. 우측 **테스트** 패널 열기
2. 첫 입력: `엑셀분석` (또는 트리거 구문 중 하나)
3. 에이전트가 "어떤 분석을 원하시나요?" → "사과의 연도별 평균은?" 입력
4. "분석할 Excel 파일을 첨부해주세요" → `과일판매.xlsx` 첨부
5. 약 5~15초 대기 후 분석 결과 출력 확인

> **체크포인트**: 결과가 일반론으로만 나오면 → 흐름이 호출되지 않았거나 파일이 빈 채로 전달된 것. 다음 디버깅 순서로 확인:
>
> 1. 흐름 실행 이력에서 `데이터JSON` 입력이 비어있지 않은지
> 2. 토픽 변수 매핑의 `Name` / `Content` 속성명이 흐름 트리거 입력과 일치하는지
> 3. 질문 노드 ②의 **파일 메타데이터 활성화** 가 켜져 있는지

## 마무리 — 손에 쥔 4단 콤보

이 17단계를 마치면 다음을 갖게 됩니다.

| 자산 | 한 줄 |
|:--|:--|
| 토픽 (질문 노드 + 파일) | 환경(Teams/Copilot)에 무관한 결정적 입력 |
| 흐름 (OneDrive 임시 저장) | 첨부 파일을 LLM 처리 가능한 위치로 이동 |
| Office Script (시트→JSON) | LLM이 읽을 수 있는 형태로 변환 |
| AI 프롬프트 (코드 인터프리터) | 정확한 수치 계산 + 자연어 요약 |

이 4단 콤보는 **다른 정형 데이터 시나리오** 에 그대로 옮겨 쓸 수 있는 패턴입니다. 다음 [S3 — 문서 자동화 5-Tier](s03-pdf-word) 에서는 PDF → Word 시나리오를 5단계로 정교하게 만들어보고, 이어 [S9 — 12 패턴 카탈로그](s09-design-patterns) 에서 이 패턴을 포함한 12 설계 패턴을 한 자리에 정리합니다.
