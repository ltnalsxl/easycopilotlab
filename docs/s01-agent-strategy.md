## ① 어떤 에이전트를 만들 것인가 (15분)

### 에이전트에게 맡기면 좋은 업무

| 특성 | 예시 |
|:-----|:-----|
| 반복적이고 패턴이 있는 질문 | FAQ, 담당자 조회 |
| 문서에서 답을 찾을 수 있는 업무 | 규정 안내, 절차 설명 |
| 데이터를 정해진 형식으로 수집 | 경비 신청, 설문 수집 |
| 여러 시스템을 조회/연결하는 업무 | 상태 확인 + 메일 발송 |

### 에이전트에게 맡기기 어려운 업무

| 특성 | 예시 |
|:-----|:-----|
| 높은 판단력이 필요 | 인사 평가, 법적 결정 |
| 매번 상황이 완전히 다름 | 창의적 기획 |
| 실수 시 큰 리스크 | 금융 거래 승인 |

### 체크리스트: "이 일을 에이전트에게 맡겨도 될까?"

- [ ] 정해진 문서/데이터로 답할 수 있는가?
- [ ] 주 5회 이상 반복되는가?
- [ ] 틀려도 큰 문제가 없거나, 사람이 확인하는 단계가 있는가?
- [ ] 담당자가 직접 하기엔 시간 낭비인가?

> 3개 이상 ✅ → 에이전트로 만들 가치가 있습니다.

## ② 지식 참조 전략 (10분)

### 지식 소스 선택 가이드

| 지식 소스 | 적합한 경우 | 갱신 주기 | 보안 |
|:---------|:-----------|:---------|:-----|
| **파일 업로드** | 핵심 문서 2~3개, 변경 거의 없음 | 수동 재업로드 | 파일 내용이 에이전트에 포함 |
| **SP 파일** | 특정 파일만 정확히 참조 | SP에서 수정 시 자동 반영 | SP 권한 적용 |
| **SP 폴더** | 문서가 자주 추가/변경됨 | 새 파일 자동 포함 | SP 권한 적용 |
| **웹사이트** | 외부 공개 정보 참조 | 실시간 | 공개 URL만 가능 |
| **Dataverse** | 구조화된 업무 데이터 | 실시간 | Dataverse 보안 역할 |

### 혼합 전략

> **실무 추천**: 핵심 규정은 **SP 파일**, 전체 문서함은 **SP 폴더**, 외부 정보는 **웹사이트**로 소스를 분리하세요. 한 에이전트가 여러 지식 소스를 동시에 참조할 수 있습니다.

## ③ 도구 구성 전략 (10분)

### 도구 선택 의사결정 트리

```
에이전트가 "행동"해야 하는가?
│
├─ NO → 지식(Knowledge)만으로 충분
│
└─ YES → 어떤 행동인가?
    │
    ├─ 대화 흐름 제어 (분기·반복·확인)
    │   └─ 📋 토픽 (Topic)
    │
    ├─ Microsoft 365 서비스 연결 (Excel, Outlook, Teams…)
    │   └─ 🔌 기본 커넥터 (Connector)
    │
    ├─ 복잡한 로직 / 여러 단계 자동화
    │   └─ ⚡ 에이전트 흐름 (Power Automate Flow)
    │
    ├─ 외부 REST API 연결
    │   └─ 🛠️ 커스텀 커넥터 (Custom Connector)
    │
    └─ 외부 서비스 도구 일괄 연결
        └─ 🌐 MCP 서버
```

### 도구별 비교

| 도구 | 난이도 | 유연성 | 대표 시나리오 |
|:-----|:------|:------|:------------|
| 토픽 | ★☆☆ | 대화 내 | FAQ 분기, 확인 질문 |
| 기본 커넥터 | ★☆☆ | M365 | Excel 저장, 메일 발송 |
| 에이전트 흐름 | ★★☆ | 높음 | 조건 분기 + 다단계 처리 |
| 커스텀 커넥터 | ★★★ | 매우 높음 | 외부 API 호출 |
| MCP | ★★☆ | 매우 높음 | 외부 서비스 도구 일괄 연결 |

## ④ 환경 변수 전략 (10분)

### 환경 변수란?

솔루션 안에서 **설정값을 이름으로 관리**하는 기능입니다. 흐름이나 토픽에서 URL, 사이트 주소 등을 직접 입력(하드코딩)하는 대신, 환경 변수를 참조합니다.

| 하드코딩 | 환경 변수 |
|:---------|:---------|
| `https://company.sharepoint.com/sites/hr` | `@{환경변수.SharePointSiteUrl}` |
| 환경이 바뀌면 모든 흐름을 수정 | **환경 변수 값만 변경** |

### 왜 필요한가?

```
개발 환경 (dev)                    운영 환경 (prod)
┌─────────────────────┐          ┌─────────────────────┐
│ ExcelTableUrl       │          │ ExcelTableUrl       │
│ = dev용 Excel URL   │   ──→   │ = prod용 Excel URL  │
│ SharePointSiteUrl   │  배포    │ SharePointSiteUrl   │
│ = dev용 SP 주소     │          │ = prod용 SP 주소    │
└─────────────────────┘          └─────────────────────┘
      흐름·토픽은 그대로, 값만 바뀜
```

### 환경 변수로 빼야 할 대표 값

| 값 | 환경 변수 이름 예시 |
|:---|:------------------|
| Excel 테이블 URL | `ExcelTableUrl` |
| SharePoint 사이트 주소 | `SharePointSiteUrl` |
| API base URL | `ApiBaseUrl` |
| MCP 서버 URL | `McpServerUrl` |

{: .tip }
> 오늘 심화과정에서 만드는 모든 흐름은 **환경 변수를 적용**합니다. S5에서 직접 만들어보고, S6~S9에서 반복 활용합니다.
