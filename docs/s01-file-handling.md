## 이 모듈에서 배우는 것

- 에이전트가 **파일을 다루는 3가지 길** 비교
- 각 방식이 **언제 적합한지** 판단 기준
- 이어지는 S2(영수증), S3(PDF) 실습이 **왜 AI 빌더 길을 선택했는지** 이해

{: .highlight }
> 기본과정 M8에서는 “지식 업로드”만 다뤘습니다. 사실 같은 PDF·Excel을 두고 **다른 길**로 가는 방법이 더 있습니다. 어느 칸을 선택할지부터 잡고 들어갑니다.

---

## 3가지 길 한눈에

| 방식 | 동작 시점 | 처리 주체 | 결과물 형태 |
|:-----|:---------|:---------|:----------|
| **① 지식으로 미리 등록** | 에이전트 만들 때 | RAG 인덱싱 (의미 검색) | 대화 답변 |
| **② 대화 중 파일 업로드** | 런타임 | **오케스트레이터(LLM)가 직접 읽음** | 대화 답변 |
| **③ AI 빌더 프롬프트 + 파일 입력** | 흐름 실행 시 | 흐름 안의 프롬프트 액션 | **정형 JSON / 다른 산출물** |

```
같은 PDF 한 장이 있다고 해보자.

① 지식                ② 대화 업로드            ③ AI 빌더
─────────────         ─────────────         ─────────────
미리 인덱싱 →         그때그때 끌어다 놓고 →    흐름 안에서 추출 →
"이 문서 뭐 있어?"    "요약해줘"               JSON → Excel/Word/메일
(자주 묻는 같은 문서)  (일회성·즉석)             (다른 시스템으로 흘려보냄)
```

---

## ① 지식으로 미리 등록 — “고정 자료”

- 위치: 에이전트 빌더 → **지식**
- 처리: 업로드 시점에 **RAG 인덱싱** → 질문할 때마다 의미 검색
- 적합한 상황: 자주 묻는 **고정된 문서** (사규, FAQ, 매뉴얼)
- 한계: 파일이 바뀌면 다시 올려야 함, **표·숫자 정확 조회는 약함**

기본과정 M8에서 5개 docx를 올린 방식이 바로 이 길입니다.

---

## ② 대화 중 파일 업로드 — “일회성 즉석 분석”

- 위치: 채팅 입력창에 파일 **드래그&드롭** (또는 첨부)
- 처리: 오케스트레이터(LLM)가 **그 자리에서 파일을 읽음**
- 적합한 상황: **매번 다른 파일**을 일회성으로 다룰 때
  - “이 계약서 종료일 찾아줘”
  - “이 PDF 3줄 요약해줘”
  - “이 Excel에서 영업1팀 사람 몇 명?”
- 한계: 한 대화 안에서만 유효, **결과물은 채팅창 답변뿐**

{: .tip }
> 이 모듈에서 짧게 시연합니다. 강의용 PDF 하나를 끌어다 놓고 “요약해줘”만 입력해보세요.

### 활성화 위치

| 항목 | 설정 |
|:-----|:-----|
| 에이전트 설정 → **파일 분석** | 켜기 |
| 지원 형식 | PDF, DOCX, PPTX, XLSX, TXT, 이미지 등 |

---

## ③ AI 빌더 프롬프트 + 파일 입력 — “산출물이 필요할 때”

- 위치: Power Automate 흐름 안의 **AI 빌더 프롬프트 액션**
- 처리: 프롬프트 입력으로 **이미지/파일/텍스트**를 받아 **정형 출력**(JSON, .docx 등) 생성
- 적합한 상황: 추출 결과를 **다른 시스템으로 흘려보내야** 할 때
  - 영수증 → Excel **행 추가**
  - PDF → Word **템플릿 보고서**
  - 명함 사진 → CRM **연락처 등록**
- 한계: 흐름 설계 필요, 가장 “손이 많이 감”

이게 S2(영수증), S3(PDF)에서 본격적으로 만질 길입니다.

---

## 어떤 길을 언제 쓰나

```
파일을 다뤄야 한다
    │
    ├─ 자주 묻는 같은 문서? ───────────→ ① 지식
    │
    ├─ 매번 다른 파일, 답변만 있으면 됨? → ② 대화 업로드
    │
    └─ 결과를 다른 시스템에 넣어야 함? ─→ ③ AI 빌더
```

### 같은 PDF, 다른 선택

| 시나리오 | 적합한 길 |
|:---------|:---------|
| 사내 규정 PDF — 신입사원이 매번 같은 걸 묻는다 | ① 지식 |
| 받아본 적 없는 제안서 — 한 번 요약만 보면 끝 | ② 대화 업로드 |
| 들어오는 모든 계약서 — 종료일·금액을 추출해 Excel로 모은다 | ③ AI 빌더 |

---

## 시연 시나리오 (15분)

| 단계 | 내용 | 시간 |
|:-----|:-----|:----|
| 1 | 같은 PDF 1개를 준비 (예: 강의 안내문) | 1분 |
| 2 | 에이전트 채팅에 PDF를 드래그&드롭 → “요약해줘” / “핵심 항목 5개” | 5분 |
| 3 | 같은 PDF를 **지식**에 등록한 다른 에이전트와 비교 | 4분 |
| 4 | 토론: “이 PDF가 100장씩 매주 들어온다면 어디로 가야 하나?” → ③번 답으로 자연스럽게 S2·S3로 연결 | 5분 |

{: .important }
> S2(영수증)와 S3(PDF)는 모두 ③번 길을 선택한 사례입니다. **단순 요약이 아니라 “다른 시스템으로 흘려보내야 하기 때문”** 입니다.

---

## 핵심 정리

> **답변만 필요하면 ①·②, 산출물이 필요하면 ③.**

| 구분 | ① 지식 | ② 대화 업로드 | ③ AI 빌더 |
|:-----|:-------|:-------------|:---------|
| 설정 비용 | 중 | **0** | 큼 |
| 같은 문서 반복 질의 | ✅ | △ | △ |
| 매번 다른 파일 | ✗ | ✅ | △ |
| 정형 출력(JSON 등) | ✗ | △ | ✅ |
| 다른 시스템 연동 | ✗ | ✗ | ✅ |
