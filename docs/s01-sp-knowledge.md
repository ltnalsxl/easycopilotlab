## 이 모듈에서 배우는 것

- SharePoint를 지식 소스로 연결하는 **두 가지 방식** 이해
- **파일 단위 연결** vs **폴더(라이브러리) 단위 연결**의 차이
- 같은 문서로 둘 다 테스트해보고 **응답 품질·범위 비교**

---

## 기본과정에서는

기본과정 M7에서는 **파일을 직접 업로드**해서 지식을 추가했습니다.

| 방식 | 장점 | 한계 |
|:-----|:-----|:-----|
| 파일 업로드 | 가장 간단 | 파일 수정 시 재업로드 필요 |

실무에서는 문서가 SharePoint에 있고, **수시로 업데이트**됩니다. 업로드 방식으로는 최신 버전을 유지하기 어렵습니다.

---

## SharePoint 연결 — 두 가지 방식

### 방식 1: 파일 단위

| 항목 | 설명 |
|:-----|:-----|
| 연결 대상 | SharePoint의 **개별 파일** (URL 지정) |
| 범위 | 지정한 파일만 참조 |
| 적합한 경우 | 핵심 문서 2~3개만 정확히 참조하고 싶을 때 |

### 방식 2: 폴더(라이브러리) 단위

| 항목 | 설명 |
|:-----|:-----|
| 연결 대상 | SharePoint **문서 라이브러리 또는 폴더** |
| 범위 | 해당 폴더 내 모든 문서 참조 |
| 적합한 경우 | 문서가 자주 추가/변경되는 경우 |

---

## 비교 실험

{: .note }
> 같은 질문을 두 가지 방식으로 연결한 에이전트에 각각 던져보고 응답을 비교합니다.

### 비교 포인트

| 항목 | 파일 단위 | 폴더 단위 |
|:-----|:---------|:---------|
| 응답 정확도 | 지정 파일 내용은 정확 | 넓은 범위에서 답변 |
| 응답 범위 | 좁음 (지정 파일만) | 넓음 (폴더 전체) |
| 최신성 | 파일 URL 고정 | 새 파일 추가 시 자동 반영 |
| 노이즈 | 적음 | 관련 없는 문서도 참조 가능 |

{: .tip }
> 실무 추천: **핵심 문서는 파일 단위**, **전체 규정집은 폴더 단위**로 혼합 사용하는 것이 가장 효과적입니다.

---

## 정리

| 상황 | 추천 방식 |
|:-----|:---------|
| "이 문서 하나만 정확히 참조해야 해" | 파일 단위 |
| "팀 문서가 자주 바뀌고 늘어나" | 폴더 단위 |
| "핵심 3개 + 나머지 전체" | 혼합 사용 |
