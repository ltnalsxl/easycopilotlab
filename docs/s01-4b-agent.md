## Step 4-4. 에이전트에 도구 등록 · 지침 작성

이제 흐름을 에이전트에서 부를 수 있게 도구로 등록하고, 언제 어떻게 호출할지는 지침으로 알려줍니다.

### 1) 도구 추가 · 입력 확인 · 저장

에이전트 `S1실습4 HOL` 의 도구 탭에서 조금 전 만들어 저장한 `meetingnote_AI` 흐름을 골라 추가하고, 입력은 흐름 트리거와 맞추어 `contentBytes (File)` · `name (String)` 을 확인합니다.

**① 도구 탭 빈 상태에서 `+ 도구 추가`**

![에이전트 도구 탭의 빈 상태 — `첫 번째 툴 만들기 / + 도구 추가`](../assets/images/s01-4/035_click.png)

**② `흐름` 탭 → `meetingnote_AI` 선택**

![도구 추가 패널의 `흐름` 탭 선택 → 목록에서 `meetingnote_AI` 선택](../assets/images/s01-4/036_click.png)

**③ `추가 및 구성` 클릭**

![도구 디테일 미리 보기 — 우측 하단 `추가 및 구성` 클릭](../assets/images/s01-4/037_click.png)

**④ 입력 `contentBytes (File)` · `name (String)` 추가**

![도구 구성 화면 — 입력 섹션의 `+ 입력 추가` 를 눌러 `contentBytes (File)` · `name (String)` 을 하나씩 추가](../assets/images/s01-4/038_click.png)

**⑤ `AI로 동적으로 채우기` 확인 후 `저장`**

![입력이 추가되고 각 입력의 `다음을 사용하여 채우기 = AI로 동적으로 채우기` 기본 값으로 잡힌 모습 — 우측 상단 `저장` 클릭](../assets/images/s01-4/039_click.png)

### 2) 지침 편집 — 도구를 직접 언급해라

에이전트가 PDF 를 보면 "내가 추출하지 말고 `meetingnote_AI` 흐름에 파일 그대로 넘겨라" 고 명시적으로 알려주는 게 핵심입니다. 아래 코드 블록의 지침을 그대로 붙여넣고, 중간의 `흐름 ` 다음에는 `/` 를 입력해 제안 패널에서 `meetingnote_AI` 도구를 직접 링크합니다.

```
당신은 회의록 표준화 에이전트입니다.
사용자가 회의록 PDF 를 첨부하면 첨부된 파일을 그대로 흐름 /meetingnote_AI 의 meetingFile 매개변수에 전달합니다.
PDF 본문 추출은 AI 빌더 프롬프트가 처리하므로 LLM 추출은 하지 않습니다.

흐름 결과의 다운로드 링크를 사용자에게 한 줄로 안내합니다.
"회의록 저장 완료: <다운로드 링크>"
```

> **포인트**: 추출 책임이 LLM(에이전트) 에서 **AI 빌더 프롬프트** 로 옮겨졌습니다. 같은 프롬프트를 다른 부서·다른 흐름에서도 재사용할 수 있는 추출 자산이 됩니다.

**① 지침 섹션 `✏ 편집` 클릭**

![에이전트 개요 화면 — `지침` 섹션 우측 상단 `✏ 편집` 으로 지침 편집기 진입](../assets/images/s01-4/040_click.png)

**② 지침 본문 붙여넣기 (213/8000 글자)**

![지침 본문에 위 코드 블록의 내용을 그대로 입력 — 213/8000 글자](../assets/images/s01-4/041_click.png)

**③ `흐름 ` + `/` 로 도구 자동 완성 → `meetingnote_AI` 선택**

![지침 본문에서 `흐름 ` 다음에 `/` 입력 → 제안 패널이 떠오르면 `meetingnote_AI` 도구 선택](../assets/images/s01-4/042_click.png)

**④ 도구 칩 삽입 확인 후 `저장`**

![지침 반영 완료 — `meetingnote_AI` 칩이 흐름 이름 자리에 들어가고 `의 meetingFile 매개변수에 전달합니다` 가 따라붙음 → 우측 상단 `저장` 클릭](../assets/images/s01-4/043_click.png)

## Step 4-5. 에이전트 테스트 — 샘플 PDF 올리고 다운로드 링크 받기

우측 상단 `테스트` 패널 열기 → 새 테스트 세션 시작 → 샘플 PDF 파일을 첨부하고 `이 파일로 회의록 만들어요` 메시지로 실행합니다.

**① 새 테스트 세션 → 메시지 + 샘플 PDF 첨부**

![테스트 패널에서 `⊞ 새 테스트 세션` 클릭 → 사용자 입력으로 `이 파일로 회의록 만들어요` 텍스트와 함께 `회의록_샘플1_줄글형식.pdf` (85kB) 첨부](../assets/images/s01-4/044_click.png)

**② OneDrive for Business 자격 증명 `허용`**

![에이전트가 `meetingnote_AI` 흐름을 호출 — `작업 중` 배지와 함께 입력/출력 디테일 카드 표시, OneDrive for Business 자격 증명 연결 프롬프트에서 `허용` 클릭](../assets/images/s01-4/045_click.png)

**③ 흐름 실행 완료 — 채팅에 다운로드 링크 응답**

![흐름 실행 완료 — 디테일 카드의 출력에 `파일이름 = AI회의록_2026-05-10T11_02_36.docx`, `파일링크 = https://...sharepoint.com/...` 표시. 우측 채팅 영역에 `회의록 저장 완료: AI회의록_2026-05-10T11_02_36.2358973Z.docx` 한 줄 응답과 클릭 가능한 링크](../assets/images/s01-4/046_click.png)

**④ OneDrive `내 파일` 에서 새 .docx 확인**

![링크 클릭 전에 OneDrive `내 파일` 에서 직접 확인 — 방금 생성된 `AI회의록_2026-05-10T...` (27.7KB, 몇 초 전) 항목이 목록 최상단에 추가됨](../assets/images/s01-4/047_click.png)

**⑤ Word Online 으로 결과 열기 — 모든 필드 채워진 회의록**

![파일을 클릭해 Word Online 으로 결과 열기 — `회 의 록` 제목 아래 1.기본 정보(회의 제목 = `DT 추진 협의회 — 1차 회의 메모`, 일시 = `2026-04-21 14:00`, 장소 = `본사 5층 대회의실`), 2.참석자, 3.안건, 4.결정 사항이 PDF 원문에서 추출된 실제 값으로 채워진 모습](../assets/images/s01-4/048_click.png)

> **검증 포인트**: AI 빌더 프롬프트가 PDF 추출 + Word 양식 채우기를 한 번에 처리해 OneDrive 에 저장되었습니다. 이전 실습 (에이전트 추출 + 흐름 채우기 두 단계) 와 비교하면 흐름이 단순해지고, 같은 프롬프트를 다른 흐름·다른 부서에서도 그대로 재사용할 수 있는 **추출 자산** 으로 분리됩니다.

## 결과 — AI 빌더가 진짜 일을 한다

이제 AI 빌더 프롬프트가 추출+채우기를 한 번에 처리합니다. 부수 효과:

- 프롬프트가 **추출 자산** 으로 독립 — 다른 흐름·다른 부서에서도 재사용
- 양식 변경 시 .docx 만 다시 업로드
- 흐름이 단순해짐 (AI 빌더 한 번 호출 + OneDrive 저장)

이걸로 이 세션의 4단계 진화가 마무리됩니다 — 실습 ① 의 5분 빌트인 경로부터 실습 ④ 의 AI 빌더 추출 자산까지, 같은 시나리오에 적용 가능한 4 가지 패턴을 손에 쥐었습니다.
